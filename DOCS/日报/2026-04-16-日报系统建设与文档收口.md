## 过程记录

### 阶段一：发现日报里缺少 BOOT-012 的实现细节

昨天写的 B5-2 日报只写了"在 hyp 侧判断 `[hpa, hpa + size)` 是否落在合法 BAR 范围内"这个结论，没有写具体怎么实现的。

重新看了内核 commit `501ca0cb907f` 的完整 diff，发现实际做了 4 件事：

1. **扩展 manifest**：在 `struct pkvm_boot_ptdev_manifest_entry` 里新增 `bars[]` 数组，每个 BAR 记录 `base` 和 `size`，启动期 `build_boot_ptdev_manifest()` 遍历所有 PCI 设备把 memory BAR 全部存进去
2. **提供命中判断 helper**：`pkvm_boot_ptdev_bar_contains()` 公式是 `hpa >= bar_base && hpa + size <= bar_base + bar_size`，封装成两个对外函数分别面向"全量 manifest 查"和"当前 VM attached 设备查"
3. **`pkvm_vm_mmu_map()` 三段分流**：命中 BAR → 直接 MMIO leaf；命中 host RAM → 走 donate；两者都不是 → 直接拒绝
4. **teardown 跳过 undonate**：BAR leaf 只拆 Guest EPT，不调 `__pkvm_host_undonate_guest()`

补完这些细节后，amend 到昨天 commit 里。
