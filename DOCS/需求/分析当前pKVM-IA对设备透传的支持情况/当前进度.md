当前进度:
- 已确认推荐主线是方案 B: `donate + pVM DMA mirror pgtable`。
- 已确认当前代码里已经存在 `pgstate_pgt -> ptdev->pgt -> IOMMU SLPTR` 这条骨架，但缺少预填充、运行时 mirror、teardown 收敛等关键补全。
- 已建立 `实施跟踪/` 目录，后续实施拆分、依赖关系、状态推进和验证矩阵统一在该目录维护。
- 已完成 T1 修复并通过当前首轮运行验证：旧 shadow spgt 残留 refcount 导致的 donate 阻塞不再复现。
- 已补齐 GitHub Issue / PR 模板，并把 `pKVM-IA` 纳入当前 superproject 的 submodule 管理，后续将按 `Issue -> pKVM-IA PR -> pkvm-x86 PR` 的闭环推进。
- 已在 GitHub 初始化远端管理对象：`pkvm-x86` Project `#3` 和当前 `12` 个 Epic / Task / Bug issues。
- 已确认 T1 对应的内核提交已经直接位于 `pKVM-IA` 默认分支，因此无法再补一条对默认分支有实际 diff 的正常 PR；后续内核改动将从 topic branch + PR 流程开始。

当前卡点:
- `BOOT-007` 已完成源码归因：当前更高置信度地指向 protected pVM 不能消费 crosvm 当前 VFIO PCI 的 config/MMIO fallback 路径，而不是 T2/T3 的 DMA mirror 主线本身。
- 下一前置任务已收敛为 B2：先处理 protected pVM 的 VFIO config/MMIO 访问路径。
- `pgstate_pgt` 当前还带有“pVM teardown 时 undonate 页面”的旧语义，需要收敛成纯 DMA mirror 语义。
- VM 销毁阶段当前是“先销毁页表，再处理 ptdev”，且现有 `pkvm_detach_ptdev()` 实际是切回 host IOMMU 视图，不等于真正 quiesce 设备 DMA。
- `failed to create vm mapping (EINVAL)` 不再仅视为无害伴随现象；它是 ECAM 只读映射失败并退回 MMIO fallback 的前置信号。
